# q4 — качество и задержка (принят 06.11.2026)

Согласованный объём: замеры всего пути, настройка кодирования и очередей,
стабильная частота кадров. Пользователь считает искажения устранёнными:
причина была в запасе обзора, при 0% их нет. Геометрия и фовеация не меняются.
Дорисовка промежуточных кадров — отдельная большая задача при необходимости.

## Исходная версия и резервная копия

Принятый q3: `16b51e7`, тег `slice-q3`. Перед q4 сохранены исходники HEAD,
незакоммиченные файлы/patch и предыдущий APK:
`build/before_q4_20261106_184953/`. Чужие изменения в рабочем дереве не сбрасывать.

## Замеры

В SteamVR-потоке новая версия WRKV 5 (HEVC): к прежнему заголовку кадра
`length:u32, sample_us:u64, pc_submit_us:u64, pose:u32` добавлены
`pose_written_us:u64, encode_started_us:u64, encoded_us:u64`, затем flags:u8
и изображение. Размер заголовка 49 байт. Ответ часов имеет те же поля,
новые три времени нулевые. Обычные мониторы и «ПК рисует» остаются на 2/4.
Новый приёмник читает 2/3/4/5. Перед чтением заголовка paced-приёмник запрашивает
версию 5 служебным сообщением из 9 байт (type=3, value=5). Сервер ждёт такой
запрос не дольше 40 мс при подключении, без запроса отдаёт прежнюю версию 4.
Поэтому старый APK продолжает работать; для всех новых замеров его надо обновить.
При задержке запроса более 40 мс безопасный fallback — версия 4, без новых
времён кодировщика; при сравнении убедиться, что измеряется версия 5.

Каждые 10 с `[q4-video]` и `[q4-layer]` показывают миллисекунды
`p50/p95/p99/max`, количество образцов. Отчёт приходит также на ПК в
`%LOCALAPPDATA%/WoRkPlace/game_host.log`.

| Этап | Границы |
|---|---|
| pose_uplink | начало формирования tracking в шлеме → обработка выбранной свежей позы хостом (каждая десятая) |
| pose_pc_to_submit | запись позы в GameLink → передача изображения кодировщику драйвера |
| pre_encode | передача изображения → начало преобразования в NV12 |
| encode | преобразование/подача кадра → получение сжатого кадра из MFT |
| send_and_network | выход MFT → полный приём пакета шлемом, включая сборку пакета и блокировки TCP |
| decoder_input_wait | приём пакета → подача в MediaCodec |
| decode | подача в MediaCodec → получение готового output buffer |
| decoded_to_texture | готовый output buffer → получение ImageReader-текстуры, включая очередь и один кадр выдачи |
| native_copy | вызов present → завершение GPU-копии, включая ожидание swapchain и glFinish |
| copy_to_layer | завершение копии → получение слоя Godot для OpenXR |
| pc_submit_to_layer | полный возраст изображения от передачи драйвером до получения слоя |
| matched_pose_to_layer | оценка от начала формирования сопоставленной позы в шлеме до получения слоя |

У последней оценки есть ограничение: SteamVR возвращает матрицу позы,
а не наш pose_id. Он ищется по матрице; одинаковые позы при неподвижной голове
не позволяют определить исходный номер однозначно. Поэтому это не точный
motion-to-photon. `pc_submit_to_layer` использует время самого изображения.
Разность часов ПК/шлема определяется по видеоканалу, рядом указан
`clock_error_ms` (половина лучшего RTT). Отрицательные значения отбрасываются
со счётчиком invalid. Первые 1,5 с декодера исключены из Java-видеостатистики;
начальные интервалы отдельно от устойчивого режима.

Передача слоя не измеряет физическое свечение пикселей, сенсорную задержку,
последний доворот и развёртку дисплея. Процентили разных этапов складывать нельзя.
Java хранит до 4096 последних образцов на этап; число и максимум — за интервал.
FPS считается по фактической длительности окна, не по условным 10 секундам.
Есть интервал новых текстур, пропуски/повторы и peak очереди готовых кадров.

## Настройки

Во вкладке «Шлем» добавлены:

- Игры: битрейт — 30–120 Мбит/с, исходно 90.
- Игры: разрешение рендера — 70–180%, исходно 140; SteamVR может дополнительно
  масштабировать его. Размер передаваемого изображения остаётся 1832×1920 на глаз.
- Игры: кадров в пути — 1–6, исходно 6; подача в MFT дополнительно ограничена
  четырьмя NV12-поверхностями, чтобы не переиспользовать занятую поверхность.
- Игры: буфер готовых кадров — 0–2 дополнительных за следующим к выдаче,
  исходно 1, что соответствует прежнему лимиту двух output buffers.

Первые три применяются при перезапуске SteamVR; последняя при переподключении.
Все ключи `game_*` в секции headset общего settings.cfg на ПК. Драйвер читает
только разрешённые числовые ключи; некорректные/NaN значения не принимаются.
Значения по умолчанию для других установок остались 6/1. На этой машине после
сравнения сохранены 3/1: вариант 3/0 ухудшал плавность, несмотря на меньший буфер.
CBR, запрос low-latency и отсутствие B-кадров сохранены. GetValue-readback
кодировщика пишется в stream.log с HRESULT: не считать неподдержанную настройку
применённой только потому, что она запрошена.

## Исправления очередей

Изображение общей D3D11-текстуры и метаданные теперь публикуются под одной
блокировкой и вместе выбираются непосредственно перед NV12-конвертацией.
Ранее между выбором метаданных и конвертацией мог прийти более новый кадр.
Ограничение кадров в пути действует с первого кадра, до первого ACK включительно.
Новый видеокадр определяется по его stream timestamp, а не pose_id: две картинки
игры, нарисованные с одной позой головы, раньше могли ошибочно считаться одной.
Отсутствие метаданных позы больше не подменяется позой предыдущей картинки.
После задержки VSync-поток пропускает просроченные такты, не выдаёт их залпом.
glFinish и владение буфером декодера сохранены; их убирать без GPU-fence нельзя.
На Quest с API 33+ готовый MediaCodec buffer теперь выдаётся в ImageReader
перед acquire, а не после: прежний порядок всегда оставлял его на следующий
кадр Godot. При необходимости ожидание уведомления ограничено 1 мс. Перед
использованием HardwareBuffer проверяется SyncFence (ожидание до 1 мс, при
тайм-ауте/ошибке кадр пропускается). В проверках fence занимал около 0,01 мс,
тайм-аутов и ошибок не было. На старых API остаётся прежний порядок.
Показатели native projection сбрасываются при clear, чтобы не смешивать сессии.

Кабельный тест выявил CRLF в выводе adb: Reverse-Usb сравнивал строку с `$`
без Trim и пропускал USB-устройство. Исправлено Trim(), есть чистая регрессия
tests/game_session_probe.ps1 с mock adb. После перезапуска helper сам создал
47902/47903/47920, шлем подключился к 127.0.0.1 без ручного reverse.

## Проверка в шлеме и сравнение

1. Установить APK после подключения USB/adb. Запустить tests/steamvr_room.
2. Дать 10–20 с прогрева. Медленно и быстро поворачивать голову, двигать
   руками/контроллерами; сетка остаётся прямой, руки/щипок/кнопки работают.
3. В другом процессе `tools/measure_game_link.ps1 -Seconds 60 -Label baseline`.
   Снимки логов и summary.json попадут в build/q4/<дата>_<метка>.
4. В рабочем мире поставить очередь 3, буфер 0. Повторить тот же тест и Wi-Fi,
   `-Label queue3_buffer0`. Сравнивать устойчивые интервалы с одинаковой нагрузкой.
5. Если задержка ниже и частота/повторы не хуже — принять параметры. Если
   растут повторы, вернуть буфер 1; отдельно пробовать 70/90 Мбит/с.
6. Проверить Serious Sam, быстрый выход, возврат рабочего режима и кабель.
   Считать срез принятым только после пользовательской проверки, затем коммит.

Проверки кода: FrameTimingsTest (процентили, сброс, отклонение неверных значений,
ограниченная память), game_quality_test (чтение, секции, пределы, неверные числа),
game_session_probe (CRLF/USB/порты), parse_probe, сборки ПК/Android и экспорт APK.
796 основных проверок + 9 Java + 4 C++ + 4 PowerShell прошли без ошибок.

## Живые результаты 06.11.2026

Quest подключён после зарядки, APK установлен. Тест — tests/steamvr_room,
1832×1920 на глаз, HEVC 90 Мбит/с, рендер 140%, фовеация 0,55, запас обзора 0.
Wi-Fi: 5 ГГц, link speed 866 Мбит/с, RSSI около -35 dBm; thermal status 0.
В таблице диапазон **процентилей отдельных 10-секундных окон**, не среднее
и не объединённый процентиль всех кадров. Последняя точка — получение слоя,
не физический дисплей. Измеренные интервалы 40–60 с после прогрева.

| Wi-Fi, исходный вывод, 6/1 | 59,93–69,91 | 65,90–99,56 | 63,69–71,02 |
| Wi-Fi, исходный вывод, 3/0 (отклонён) | 52,72–86,79 | 64,20–141,90 | 33,77–55,70 |
| Wi-Fi, исходный вывод, 3/1 | 62,44–74,16 | 77,38–91,29 | 62,52–69,81 |

USB-повтор дал p50 42,22–47,17 мс, 70,91–71,01 текстур/с. В имени его каталога
ошибочно осталось wifi: actual endpoint был 127.0.0.1 из-за старой локальной
копии настройки. summary.json исправлен с transport=usb и пояснением;
в Wi-Fi-результат он не включён. Для следующего Wi-Fi-замера при остановленном
приложении синхронизирована локальная копия настройки, хост подтвердил LAN-IP.
Первый cable_q3_b1 без соединения помечен скриптом как неуспешный, исключён.
Теперь измерительный helper сохраняет transport/endpoint и предупреждает,
если метка расходится с фактическим подключением.

Кодировщик подтвердил low_latency=1, CBR=0, bitrate=90000000. GetValue B-frames
вернул E_NOTIMPL: отсутствие перестановки не выводить только из этой настройки.
Сырые журналы, интервальные summary.json и comparison.json — build/q4/.
Изменения очередей сами по себе не дали надёжного выигрыша Wi-Fi; основной
измеренный выигрыш дал порядок выдачи ImageReader. RF-условия и фазы вывода
меняются, поэтому не обещать одинаковую задержку во всех играх.

Итоговые настройки на машине: авто-связь восстановлена, 90 Мбит/с, 140%,
очередь 3, буфер 1, FOV 0. Тестовая комната оставлена для визуальной проверки
плавности, быстрых поворотов, рук/контроллеров и выхода пользователем.
После сравнения пользователь сообщил, что сильной разницы по ощущениям не
заметил, и разрешил коммит. Снижение задержки относится к указанным замерам
тестовой комнаты, а не к подтверждённому субъективному улучшению во всех играх.

## Сравнение двумя кнопками и возврат после игр (06.11.2026)

По просьбе пользователя в player добавлена локальная панель поверх игры,
внизу поля зрения: «Как изначально» и «Тест q4». Удержание триггера/щипка 0,45 с,
начатое на кнопке, переключает профиль без перезапуска SteamVR и видеодекодера.
Точка у кнопки показывает наведение; выбранная кнопка выделена, есть подпись.

- «Как изначально»: прежний порядок acquire → release (один кадр ожидания),
  очередь ПК 6, один запасной готовый кадр.
- «Тест q4»: release → acquire текущего кадра с SyncFence, очередь ПК 3,
  тот же запасной кадр. Битрейт, разрешение, FOV и фовеация не меняются.

Это сравнение порядка выдачи/очередей, а не полный откат исходников к q3:
общие исправления метаданных, ограничения занятых NV12-поверхностей и USB
сохраняются в обоих вариантах. Ручные настройки очереди/буфера читаются при
запуске; нажатие кнопки применяет указанные значения пресета и сохраняет их.
После переключения сбрасываются интервальные метрики. Нажатие локальной
кнопки перехватывается до отпускания, триггер/щипок в игру не передаётся;
позы и скелет остаются. Удержание, начатое до появления панели или вне кнопки,
не включает профиль. Кнопки работают с Touch и оптическими руками.
Динамическая очередь идёт через atomic game_profile в GameLinkV7.
В журнале подтверждены исходный профиль 0 и нажатие пользователем профиля 1.

Пользователь сообщил зависание «выход из SteamVR» до переподключения USB.
На ПК за 1 с уже завершилась сессия и стартовал рабочий сервер, поэтому
добавлен явный games_leaving с предыдущим режимом, задержка завершения 0,15 с
для доставки, и защита от повторного выхода. В шлеме выход немедленно снимает
признак connected, зависший статус сбрасывается через 4 с. HeadsetRoot умеет
находить другой режим через TCP localhost, не только UDP: USB не переносит
Wi-Fi discovery. Проверяется только порт другого режима, чтобы не вытеснить
собственное подключение. «Только Wi-Fi» исключает USB-пробу.
Пауза adb до 3 с в session helper теперь не продолжает обход остальных портов,
если уже выбран выход; это укладывает завершение в срок ожидания сторожа.

Проверено в шлеме: закрытие тестовой комнаты получило подтверждение и вернуло
мир с 5 мониторами на 127.0.0.1. При принудительном завершении game_host,
без выходного ACK и с временно отключённым Wi-Fi, журнал показал
«USB отвечает: мир в шлеме» и подключение рабочего мира к localhost.
Во время снятия журнала завис сервер adb на ПК; для доступа к журналу он
перезапущен. Wi-Fi затем включён и проверен, физических требований к
переподключению в коде нет. Этот эпизод adb не считать исправленным в драйвере.

22 проверки UI/удержания/захвата ввода, протокола и TCP-переходов прошли.
GameSession probe — 5 проверок, включая отмену USB-опроса при выходе.
Бэкап перед доработкой: build/q4_ab_backup_20261106_214537 (исходники и APK).
Пользовательская проверка проведена, коммит разрешён 06.11.2026.

# q2 — контроллеры SteamVR, 06.11.2026

Реализован ввод физических Touch-контроллеров через существующую связь:
позы grip/aim передаются в GameLink, драйвер публикует grip, профиль
oculus_touch и штатный input profile SteamVR. Модель — controller_box.
Для направлений aim SteamVR использует преобразования профиля; геометрия
наведения в игре требует проверки пользователем.

Кнопки A/X, B/Y, стик и его нажатие, курок/хват (аналоговые значения и
нажатия), касания A/X, B/Y, курка, стика и площадки большого пальца.
Меню передаётся системному входу SteamVR; оно может перехватываться SteamVR
и не обязано появляться в панели приложения. Двойное нажатие/удержание меню
по-прежнему выполняет быстрый выход WoRkPlace.

Вибрация: SteamVR VREvent_Input_HapticVibration → атомарный mailbox на руку
в GameLinkV2 → GameBridge.take_haptics → сообщение haptic → OpenXRInterface
шлема. Длительность ограничена 5 с, амплитуда 0–1, частота 0–1000 Гц.
Mailbox хранит последний запрос каждой руки, это не очередь всех импульсов.

Потерянные/просроченные позы инвалидируются, значения ввода обнуляются.
Синтезированные профили hand_interaction исключены; преобразования рук в
контроллеры и skeletal input этим срезом не реализованы.

## Руки, следующий срез

Пользователь подтвердил работоспособность контроллеров и запросил руки.
GameLinkV3 передаёт wrist и 31 parent-local transform для Skeletal Input;
26 runtime joints проверяются по флагам position/orientation valid, source
должен быть UNOBSTRUCTED (контроллерный синтез исключён). Пять auxiliary
костей используют положения кончиков относительно корня. При активном
контроллере он имеет приоритет. При потере руки поза инвалидируется.
SteamVR успешно создал оба skeletal component (result 0); фактическая
ориентация пальцев в моделях игр ещё не проверена. Различия систем осей
OpenXR и стандартных bind poses SteamVR могут потребовать коррекции.

В тесте полученные на ПК joints показываются точками и линиями. Это
диагностика самой передачи: при WORKPLACE_HAND_PROBE=1 хост отдаёт только
локальному тесту на 127.0.0.1:47923 исходные руки. Это не проверка того,
как конкретная игра читает SteamVR Skeletal Input. Тест скрывает руки при
потере данных через 0,5 с. Проверить раскрытую ладонь, кулак, каждый палец,
поворот кистей и переключение руки/контроллеры. Вибрации/кнопок у голой руки
не синтезируем; щипок как нажатие этим изменением не добавлен.

Исправление после проверки «руки не появились»: Quest отдаёт source=UNKNOWN
(0), хотя joints=182 и wrist_flags=63, т.е. суставы валидны и отслеживаются.
Фильтр source==UNOBSTRUCTED отбрасывал их. Теперь UNKNOWN принимается при
отсутствии отслеживаемого физического контроллера той же руки. CONTROLLER и
NOT_TRACKED исключены. Тестовая визуализация использует тот же fallback.

После проверки меню SteamVR: ориентация optical grip строится геометрически
от запястья к middle metacarpal, а не напрямую из ориентации joint. Wrist bone
сохраняет offset относительно нового grip frame. Щипок thumb tip/index tip
даёт trigger click: порог входа 25 мм, отпускания 35 мм. Физический контроллер
сохраняет приоритет. Сборка успешна, ориентация луча и нажатия в меню требуют
визуальной проверки пользователя; не считать оси skeletal bind pose проверенными.
Следующая доработка: пользователь попросил направление как в основном приложении.
Хост передаёт сохранённую секцию ray при hello. Player использует тот же
PointerMath: shoulder/rotation blend, deadband/adaptive smoothing, yaw/pitch и
aim_offset каждой руки; при use_runtime_aim используется aim среды. Это общий
расчёт базового направления; вся логика жестов/заморозки курсора main.gd сюда
не переносилась. Native bridge использует эту aim-позу как root устройства и
сохраняет относительную позу скелета. Сборка и установка успешны.

06.11.2026: после исправления пользователь подтвердил «работает» и разрешил
коммит. Контроллеры приняты ранее. Передача рук в тесте подтверждена; совместимость
скелетной анимации со всеми играми этим подтверждением не устанавливается.

## q3: совместимость игр и отдельные позы (06.11.2026)

В меню луч рук был правильным, в игре наклонялся вниз; пользователь сообщил,
что в Serious Sam VR TFE не работает ходьба стиками. Старый журнал игры с Link
показывал `oculus / Meta Quest 3S / Oculus`, с нашим драйвером —
`workplace / WoRkPlace Quest / WoRkPlace`. Драйвер теперь отдаёт сведения
о настоящем Quest 3S и семейство oculus. Контроллеры используют идентификаторы
совместимости Touch из штатного touch_profile SteamVR; простые модели остаются.
Объявлены SupportedButtons (0,1,2,7,32,33,34) и legacy-типы осей
Joystick, Trigger, Trigger, None, None. Отсутствие этих свойств могло мешать
старым играм выбирать правильный способ движения; причинная связь пока гипотеза.

Через CreatePoseComponent/UpdatePoseComponent явно обновляются `/pose/tip`,
`/pose/openxr_aim`, `/pose/handgrip`, `/pose/openxr_grip`. Смещения вычисляются
относительно raw-позы устройства. Для физических контроллеров raw остаётся grip;
для оптических рук raw остаётся настроенным лучом основного приложения, чтобы
сохранить работу старых игр и меню. Геометрическая поза хвата передаётся отдельно
в GameLinkV6 (`hand_grip`), скелет остаётся относительно raw. Ранее отдельной
grip-позы рук и явных компонентов OpenXR у простого render model не было.
Игры, которые сами наклоняют оружие относительно raw, требуют отдельной проверки.

Windows-модуль и драйвер собраны. SteamVR создал все 8 pose-компонентов с result=0,
ошибок обновления не зарегистрировано. Serious Sam запущен через Steam (552450);
его новый журнал подтверждает `oculus / Meta Quest 3S / Oculus`.
Движение и направление луча внутри игры ожидают проверки пользователем.
После проверки пользователь сообщил «вроде как работает» — предварительное
подтверждение, без отдельного уточнения каждого симптома. В конце сессии
18:46:39 SteamVR сообщил scene_pid=0, хост через 3 с начал возврат предыдущего
режима. Перед закрытием около 71–72 кадров/с, сопоставление кадров с позами
без промахов; это не измерение полной задержки до экрана шлема.
APK не менялся: вся правка на ПК. Резервная копия изменяемых файлов:
`build/input_backup_20261106_182736`.

Добавлена диагностическая программа `tests/steamvr_input_probe.cpp` для чтения
legacy GetControllerState. Требует официального SDK `native/openvr/openvr.h`
(как openvr_driver.h, не хранится в git), собирается MSVC C++17, `/I native/openvr`.
Запуск: `build/steamvr_input_probe.exe "<SteamVR>/bin/win64/openvr_api.dll" 10`.
Печатает свойства и значения стиков/кнопок; background-вводу SteamVR может
отказывать в фокусе. В таком случае ноль samples не означает исправность стиков.
Опциональный `--scene` после длительности получает фокус для отдельной пробы
и перехватывает VR: не запускать одновременно с игрой. Проверка свойств дала
axis0=2 (Joystick), supported=700000087; background-проба не получила samples.

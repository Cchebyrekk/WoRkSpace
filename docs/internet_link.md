# Интернет-связь: сервер на ПК

Срез s (ветка и тег `slice-s`, включён в `main`). Первая привязка готовится по доверенному USB;
после неё шлем использует сохранённый вход и указанный пользователем адрес ПК.
Сервер на сторонней машине не требуется. Через Tailscale пользователь подтвердил
картинку, управление между разными сетями и автоматическое восстановление;
качество и стабильность продолжают проверяться.

## Как устроено

- `internet/desktop.py` — окно сервера на ПК: создание кода, сравнение проверочных
  символов, подтверждение запроса, список привязок и отзыв доступа.
- `internet/server.py` — один входящий TLS-порт 47930. После проверки устройства
  соединение направляется только в разрешённые локальные порты WoRkPlace.
  Адрес назначения, переданный клиентом, не используется; доступа к произвольным
  службам ПК нет. Удалённого административного интерфейса нет.
- `internet/pairing.py` — одноразовый восьмизначный код на две минуты,
  ограничение попыток, явное подтверждение на ПК, постоянные привязки в SQLite.
  В базе хранятся хеши токенов; незавершённые коды теряются при перезапуске.
- `InternetLink` — управление поверх TLS вместо TCP. Формат сообщений LAN
  не меняется. Привязка хранится только в приватном каталоге приложения Quest,
  отдельно от общих настроек ПК. Ключ входа не копируется в `settings.cfg`.
- `InternetTransport.java` — видео и звук через отдельные TLS-соединения.
  Доверяется только сертификату ПК, переданному при подготовке по USB.
  При ошибке настройки не выполняется откат к открытому сетевому соединению.
- `headset/src/internet_setup.gd` — панель ввода кода в шлеме, сравнение символов,
  выбор интернета или локальной связи. Панель появляется перед пользователем
  внутри существующего мира: не удаляет его, не создаёт XR-камеру и не следует
  за поворотом головы. Ожидание подтверждения ограничено;
  `C` отменяет текущий ввод. После входа панель скрывается.
  Перемещение и управление миром работают и при открытой панели. Кнопки используют
  обычные указатели мира; перехватывается только наведённая на PIN рука. Для
  режима «ПК рисует» есть видимый луч с переводом позы через текущий XROrigin.
  При смене связи приёмники сохраняют последний кадр экранов до новых потоков.

## Первая проверка

1. Запустить `tools/internet_server.cmd` на ПК (нужны установленный Python 3.12
   с Tkinter и Godot из окружения проекта). Ввести адрес подключения только
   в окне приложения. Для начала использовать локальную сеть.
2. Установить новую сборку Quest. В окне ПК передать настройки в Quest по USB:
   передаётся публичный сертификат и адрес, а не секрет входа. Приложение шлема
   перезапустится. На время привязки USB пробрасывает дополнительный порт 47930.
3. Создать код в окне ПК. В настройках шлема выбрать «Связь с ПК → интернет»,
   ввести код и запомнить проверочные символы. Кнопка «Кабель / Wi-Fi» возвращает
   к обычным экранам: сравнить символы с окном ПК и подтвердить привязку там.
   Затем снова выбрать «интернет» в настройках шлема; повторный код не нужен.
4. Для локальной проверки TLS-порта разрешить в брандмауэре только шлюз:
   `tools/internet_firewall.ps1 -LocalOnly` от администратора. Откат — тот же
   скрипт с `-LocalOnly -Remove`. Для доступа из любых сетей правило без
   `-LocalOnly` требует отдельного явного согласия; откат — `-Remove`.
   Обычные порты 478xx/479xx не открывать для интернета.
5. Проверить без USB: экраны, ввод, звук, режим «ПК рисует», SteamVR и возврат.
   Затем отозвать устройство в окне ПК: активные каналы должны закрыться.

Пункт «Связь с ПК» получает вариант «интернет». Настройки рабочего режима
по-прежнему определяются ПК; шлем спрашивает его режим по защищённому каналу.
Для обычной работы оставлены варианты «кабель или Wi-Fi», «только кабель»,
«только Wi-Fi».
Кнопки выбора способа связи цикличны в обе стороны: после «интернет» идёт
«кабель или Wi-Fi», перед «кабель или Wi-Fi» — «интернет».
Если защищённый сервер недоступен, через ограниченное время появляется панель
с возвратом к локальной связи; устройство не оставляется в бесконечном ожидании.

## Доступ из другой сети

### Проверка через Tailscale

Установить официальный клиент на Windows и универсальный Android APK в Quest.
Войти в один аккаунт на обоих устройствах и включить соединение; в Quest
подтвердить системное разрешение VPN. Совместимость и качество на шлеме
проверяются отдельно, установка APK сама по себе их не подтверждает.
В окне сервера нажать «Использовать адрес Tailscale этого ПК», затем передать
настройки в Quest по USB. Кнопка читает только собственный адрес через
`tailscale ip -4`, без списка устройств, внешних адресов и сетевой диагностики.
Сертификат и привязка WoRkPlace сохраняются. Нужен работающий шлюз TCP 47930
и доступ к нему через брандмауэр; переадресация на роутере не требуется.
Отключить USB, перевести Quest в другую сеть и выбрать «интернет».
Пользователь подтвердил картинку и управление между разными сетями, но
сообщил о периодических обрывах с последующим восстановлением. Стабильность
пока не принята. Прямой путь предпочтителен для видео; путь через ретранслятор
может ограничить качество и задержку. Фактический тип пути в этой проверке
не определялся.
При временном обрыве привязанное устройство продолжает автоматический поиск
без нового PIN. Панель восстановления закрывается при возврате управления,
проверка режима ПК продолжается и при открытой панели. Экраны рабочего мира
сохраняют последний кадр до нового списка потоков после переподключения.

### Прямой входящий порт

Пользователь согласовал сервер на своём ПК и настройку входящего порта.
На маршрутизаторе потребуется направить только TCP 47930 к этому ПК и указать
доступный извне адрес в окне приложения, затем обновить публичные настройки
подключения в Quest. Обновление адреса и публичного профиля тем же окном по USB
сохраняет привязку: новый PIN не требуется, если сертификат ПК не менялся.
Для WAN-проверки отключить USB и подключить Quest к другой сети, оставив ПК
в его исходной сети. Проверить повторный вход, экраны, ввод, звук и возврат;
в отчёте достаточно этапов и кодов ошибок без сетевых идентификаторов.
В сообщении подключения и журнале шлема используются обезличенные коды:
`TCP_CONNECT` / `TCP_TIMEOUT` — не установлен сетевой канал,
`TLS_ERROR` / `TLS_TIMEOUT` — не установлен защищённый канал,
`AUTH_FAILED` / `DEVICE_NOT_PAIRED` — сервер не принял сохранённый вход,
`PC_SERVICE_UNAVAILABLE` — шлюз доступен, но локальная служба ПК недоступна.
Сами адреса, PIN, токены и сертификаты в этих сообщениях не выводятся.
При запрете входящих соединений на стороне сети/оператора
такая схема без внешнего посредника не заработает. Автоматическое обнаружение
публичного адреса, UPnP и изменение настроек маршрутизатора не выполняются.

Сертификат и база привязок находятся в пользовательском каталоге WoRkPlace
в подпапке `internet`. Удаление сертификата меняет личность сервера и требует
повторной подготовки Quest по USB. Не хранить эти файлы в репозитории.

## Выполненные проверки

### Настройки качества

На вкладке «Шлем» отдельно сохраняются `[headset] internet_video_mbps`
(2–60 Мбит/с на экран, по умолчанию 6) и `internet_video_fps`
(15–90 кадров/с, по умолчанию 30). Они заменили фиксированный экспериментальный
потолок и действуют независимо от параметров локального видео. Новые значения
передаются серверу после существующей паузы стабилизации 1,5 с; потоки
перезапускаются, заново открывать приложение не требуется. Можно восстановить
исходные 30 Мбит/с и 60 кадров/с. Разрешение экрана не меняется.

### Сравнительный замер до добавления настроек

Новый замер в другой сети (50,8 с, пять экранов, пять журналируемых интервалов):
принятие кадра 95–265 мс, декодированный кадр 124–344 мс, максимальное
измерение 1729 мс, неопределённость часов 57–58 мс, поток 1,8–5,7 Мбит/с.
Это показатели приёмника, а не полная задержка до фотонов. За этот отрезок
новых обрывов не зарегистрировано. Исходный предел кодирования — 30 Мбит/с
и 60 кадров/с на экран; переменный фактический трафик существенно ниже предела.
Для сравнения введён экспериментальный потолок только в режиме «интернет»:
6 Мбит/с и 30 кадров/с на экран (более низкие настройки пользователя сохраняют
приоритет). Разрешение, число экранов и сохранённые значения не меняются.
Это ограничение пиков и нагрузки декодера, не оценка пропускной способности
и не адаптивный битрейт. В показатели добавлен RTT управляющего канала.

Повтор после установки (50,6 с, те же пять экранов): четыре из пяти средних
интервалов декодированного кадра 111–135 мс, один 456 мс; максимальное
измерение 939 мс, неопределённость часов 57–60 мс, фактический поток
2,0–2,6 Мбит/с. RTT управления 125–141 мс в четырёх точках, в одной 958 мс.
Новых обрывов за этот отрезок нет. Реальные запросы 6000 кбит/с и 30 кадров/с
подтверждены в журнале. Короткие последовательные замеры с пользовательской
нагрузкой не доказывают причинного улучшения от настройки; пики сохраняются
и затрагивают управление, а не только декодер. Проверка читаемости и удобства
экспериментального предела остаётся пользователю.

21 проверка Python, включая реальный клиент Godot → TLS → двоичный поток,
одноразовость и срок кода, невозможность подтверждения чужим ПК, повторный вход,
отклонение недоверенного сертификата и закрытие потока при отзыве доступа.
Проверено, что чужие неверные входы не исчерпывают лимит доверенного устройства.
Основной набор Godot: 796 проверок без провалов; возврат из игр: 15 без провалов.
Java-приёмники компилируются. Пользователь подтвердил работу защищённой связи
в одной сети. Исправленная PIN-панель и управление миром приняты пользователем;
через Tailscale пользователь подтвердил доступ между разными сетями; остаются
периодические обрывы. Исправление поведения панели при восстановлении проходит
54 автоматические проверки (включая независимые настройки интернет-видео); автоматический
возврат после обрыва подтверждён пользователем на шлеме.

Для повторения тестов сначала создать тестовую пару сертификат/ключ:
Godot с `--headless --xr-mode off --path . -s tools/internet_certificate.gd --`
и абсолютным путём `build/internet_test_tls` после разделителя. Затем
`py -3.12 -m unittest internet.test_pairing internet.test_server -q`.

Основа TLS — [Python ssl](https://docs.python.org/3.12/library/ssl.html) и
[asyncio streams](https://docs.python.org/3.12/library/asyncio-stream.html).
Сертификат создаётся встроенным [Godot Crypto](https://docs.godotengine.org/en/stable/classes/class_crypto.html).

## Причина перехода

Пользователь видит изменение формы окна при повороте головы, в том числе без
фовеации. Причина пока не доказана. Текущий player.gd показывает видео на
плоскостях в мире: поза кадра → плоскость → текущая камера Godot → OpenXR.
Новый путь должен устранить эту дополнительную геометрию.

## Реализация

1. Отдельная Android arm64 GDExtension в headset/native; не смешивать её сборку
   с Windows-модулем. Существующий native/godot-cpp поддерживает NDK 28.1.13356709.
2. Наследник OpenXRExtensionWrapper, зарегистрированный до инициализации OpenXR.
   Через get_openxr_api(): register_composition_layer_provider; слой
   XrCompositionLayerProjection, две XrCompositionLayerProjectionView.
   Использовать текущую сессию и get_play_space(), не создавать вторую сессию.
3. Собственные swapchain для глаз. GPU-копирование EGLImage декодера с разворотом
   фовеации в GLES3; без CPU-копии. Выполнять на потоке рендера. Сохранять и
   восстанавливать GL state, не портить рендер Godot.
4. Один неделимый пакет кадра: изображение, идентификатор, время, две позы глаз,
   два FOV. Метаданные относятся к фактически отправленной картинке после всех
   преобразований на ПК. Не подставлять новую позу к старой картинке.
5. Владение буфером декодера сохранять до завершения GPU-копии; смену сессии,
   разрыв связи и освобождение swapchain обрабатывать на соответствующем потоке.
6. player.gd переключает только игры на новый слой. При отсутствии готового
   слоя — диагностический статус, а не скрытое смешение двух путей.
   Локальный интерфейс и аварийный выход остаются доступными.

## Проверки перед установкой

- Порядок глаз, знаки FOV, вертикальная ориентация текстуры, область обрезки
  декодера; в тестовой сетке прямые линии не изгибаются при повороте.
- Фовеация и обратное преобразование дают исходные направления лучей.
- При неподвижном исходном кадре слой сохраняет его позу и FOV; доворот
  выполняет runtime. Не утверждать правильность по одному совпавшему pose_id.
- Нет активного слоя до первого полного кадра и после разрыва соединения.
- Замеры отдельно: сеть, декодирование, GPU-копия, submit; счётчик submit
  не равен измерению физического показа пикселей дисплеем.
- Проверка в шлеме: медленный поворот на неподвижное окно, быстрый поворот,
  наклон головы, выход и повторное подключение. Коммит только после приёмки.

## Первая реализация

Сборка из headset/native: `py -3.12 -m SCons platform=android arch=arm64
target=template_debug -j8`, ANDROID_HOME=C:\Android\Sdk. Заголовки OpenXR
release-1.1.54 из KhronosGroup/OpenXR-SDK в include/openxr (локальная зависимость).
Библиотека — addons/workplace_projection/bin/libworkplace_projection.so.
Исходный APK для отката сохранён в build/projection_backup/workplace_headset.apk.

Singleton GameProjection принимает EGLImage и метаданные из player.gd,
разворачивает фовеацию в две swapchain, подаёт проекционный слой под прозрачный
интерфейс Godot. На первом этапе требуется текущий EGL context при вызове
present (однопоточный Compatibility); при его отсутствии слой не включается,
в журнал пишется ошибка. GPU-копия пока завершается glFinish для сохранения
времени жизни буфера Java — оптимизировать после проверки геометрии.
